性质：方案草案。没有运行任何计算，不改 local_E v1、Ω、默认 head，也不训练。
依据：`DESIGN_2026-10-23_groupwise_dummy.md`（全文）、`../2026-11-06_acetamide_fidelity/RESULT.md`、`../2026-11-07_analytic_longrange/ACCEPTANCE_2026-11-07.md`、`../2026-10-25_head_retrain/RESULT.md`。

## 1. 校准的是什么量，为什么关键

同一 carved 簇上：

    r(x) = C^ML(x) − C_bb(x) = (Σ learned + X) − C_bb，  C_bb = E_bb(L+Ω) − E_bb(L) − E_bb(Ω)
    δU_head(x) = δU_bb(x) + r(x)

参考量是 backbone 耦合 C_bb，也就是 head 的训练目标（T = C_bb − X），不是物理真值；物理精度另列。

对自由能的影响（精确恒等式，两个目标共用同一个 V）：

    Δa ≡ a_0[head] − a_0[bb] = −RT ln ⟨exp(−β r)⟩_{V + δU_bb}

如果 r 是常数 c，那么 Δa = c，而且溶剂腿里 a_K = 0，它会一比一进入 ΔF_solv^E。
acetamide 固定面板上 nvar-b 的平均 r = −20.38 kJ/mol（约 8 RT）。不处理的话，这个水平会直接进模型溶剂自由能。
文献 acetamide 水合自由能约 −40 kJ/mol【未核实，未在 E3D 体系上复测】，作为量级参照。

## 2. 先分清误差从哪来（只诊断，不改目标）

**第 1 步：r 随 Ω 水数 N 的变化（0 MD）。**
已有线索：旧 head 的 test_scale（41 原子配体）上，r 的均值随 n_solv 漂移，旧 head 在 n=20／50／100 分别是 −0.007／−0.115／−0.303 eV（`head_retrain/RESULT.md`）。head 训练配方是 ≤24 个水（MODEL_DEFINITION §2.2）；nvar 的训练簇大小【未核实】。
- 构型：acetamide 原输入，加 4 个已存短 MM 帧，共 5 帧。
- N ∈ {10, 16, 24, 32, 40, 50}。改 N 只用于诊断，不改 local_E v1 的 Ω=50；簇大小按 §6 显式记录。
- 量：每帧每个 N 的 r、C_bb、学习通道和显式 Coulomb。
- 成本：30 次 head 查询，加 90 次 backbone forward，CPU。耗时依据：上一轮 5 次查询加 9 次 forward 用了 26.1 s（`diagnostic.json`），据此估计这一步几分钟内跑完；小 N 更快。
- 局限：5 帧高度相关，只能看 N 方向的趋势，看不出构型分布。

**第 2 步：独立 MM S0 帧上 r 的分布（需要新 MD，预算由用户定）。**
- 独立准备的 acetamide S0 MM 生产，帧间隔按实测相关时间取。
- 报告 r 的均值、sd、分块 SE，r 与 (C_bb − C_MM) 的相关，以及 r 与 Ω 组成的关系。
- 按“准备”划分校准集和验证集，不在同一条轨迹里切。
- MM 单步耗时还没在 acetamide 上测过，先冒烟一段再给计划表。

**第 3 步：模型目标区域（η=1）上的 r。**
现有的只有 74 步的入口冒烟链，只能做描述。真正覆盖需要 η 运行，不在本方案里。

## 3. 可选的校准方式（只比较，选择权在用户）

| 方式 | 修什么 | 代价／与设计的冲突 |
|---|---|---|
| K0 不校准 | — | 报告 r 的统计，Δa 记为未知；模型自由能带着已知的水平偏差 |
| K1 常数平移 c | 只修水平 | 响应误差还在（面板上减掉均值后 RMSE 1.74，短 MM 帧响应 RMSE 3.78 kJ/mol）。c 分到各原子需要另定约定，和 §7.5“不按原子数／能量比例分摊”冲突；只能用于总量 |
| K2 总量改用 backbone：δU = C_bb − C_MM，head 只管原子拆分 | 水平和响应都改成 backbone 的 | 这是目标修改：§7.1 定义 C^ML = head + 显式 Coulomb，所以需要用户决定并单独建版本。Σ_i δu_i 与 δU 的差 −r 单列为残差，不分摊。每次查询多 3 次 backbone forward |
| K3 补训练 head | 训练覆盖不足 | 只在第 1、2 步指向覆盖或外推问题时才讨论；没有授权自动重训 |

## 4. 怎么读结果（不设新门限，只报告实测值）

- r 随 N 单调漂移，且漂移量明显大于同一 N 下的帧间 sd → 簇大小外推问题，K2 或 K3 是候选。
- 独立 MM 帧上 r 接近常数（sd 远小于 |均值|，且与 C_bb − C_MM 无关）→ K1／K2 能修掉大部分，原子约定仍由用户定。
- sd(r) 和 backbone 自身的响应（短 MM 帧 RMS 8.25 kJ/mol）在同一量级 → 常数平移不够。

## 5. 和后端验收的关系

后端对 r 几乎没有影响（输入帧上 −20.13 → −20.03 kJ/mol，只有单构型的依据），所以这里在现行位移模板后端上做，不等后端的决定。
